# RCP2 ループ展開の設計メモ

更新日: 2026-10-24  
対象ブランチ: `feature/rcp2-parser-skeleton`

## 目的と範囲

F8/F9 のカウント付きループと FC の同一小節参照を、安全に中間イベント列へ展開するための設計メモ。ここでは実装を行わず、資料で確認できる挙動、実装上の推論、未決事項を分離する。

根拠となる外部資料:
- [JMPlayer RCP format notes — Commands / FC same-measure repeat](https://github.com/jihodaya/jmplayer/blob/main/docs/formats/en/rcp.md)
- [ValleyBell/MidiConverters rcp2mid.c](https://github.com/ValleyBell/MidiConverters/blob/master/rcp2mid.c) — 挙動比較用。実装コードは流用しない。

## 資料から確認できる挙動（外部資料の記述）

### F8 / F9

- F9 はループ開始コマンドで、時間を進めない。
- 実装の第1段階では、F8 の p0 が 1〜126 の有限反復数である場合に限り、F9/F8 の単純ループとネストループを展開する。F8 の回数を「ループ本体の総通過回数」と解釈する。これは ValleyBell の参照コードのカウンター挙動と一致する。
- 展開は MIDI/tick 変換前にレコード列として行い、F8/F9 レコード自体はタイムラインへ出さない。繰り返される各レコードは元の順序を保つ。
- F8 はループ終端コマンドで、step フィールドは時間ではなくループ全体の反復回数を表す。
- F8 の step=0 の意味は未確定。参照コンバーターが末尾に追加小節を出すケースは、形式仕様と参照コンバーター固有の挙動を分けて扱う。実装では step=0 と step>=0x7f を明示的に拒否する。
- ループ範囲に対して、ネスト、複数の F9/F8、対応しないペアの扱いは、資料だけから一般化せず、追加調査と合成テストで確定する必要がある。

### FC

- FC は F8/F9 のカウント付きループとは別の「同一小節の繰り返し」コマンド。
- FC の参照位置は `p1 | (p2 << 8)` のバイト位置で、トラック先頭を基準とし、44-byte トラックヘッダーを含む。p0/step を小節番号として使わない。
- FC の参照先は、ファイルの実測 byte offset に対応づける必要がある。単に「何小節目」や「次の FD」だけで終端位置を決めない。
- FC を処理中に別の FC に遭遇した場合は tail-call として扱う。参照資料では、チェーン中の FC が新しい戻り先を push せず、1つの小節分の繰り返しを継続する。
- 繰り返し終端は位置関係で決まる。FC が参照先と同じ byte offset にある場合はその参照を続ける。参照先より後の位置で FC に到達した場合は、次の小節へ進んだものとしてその繰り返しを終える。
- 同じ FC レコードを1つの FC チェーン内で2回以上処理しない。資料では循環を避けるため、単純な深さ上限を代用しないことが強調されている。

## 現行コードとの接点

- `sequence_event` は4-byteレコードの command と p0/p1/p2 を保持する。
- `intermediate_event` は track 内の `record_index` と raw レコードを保持する。
- `expand_note_key_signature_tempo_timeline` の入口で、F8/F9 の有限反復数 1〜126 をレコード列として展開する。単純ループ・ネストループの合成テストを追加した。
- F8/F9 の step=0、step>=0x7f、不対 F8/F9 は拒否し、出力を空にする。展開レコード予算は 1,000,000 件。
- FC と 0x98 は引き続き未対応コマンドとして拒否する。ループを含む文書全体のテストと CI は、実行結果を確認するまで未検証として扱う。
- FC の byte offset は固定4-byteレコードという前提なら、トラック先頭から `0x2c + record_index * 4` で導出できる。ただし、これは解析済みの各レコードが元データと同じ位置・順序にあることを前提にした実装上の推論であり、実装前に `parse_tracks` の長さ境界とオフセットの対応をテストする。
- ループ展開は、MIDI化や秒変換より前のトラックローカルな段階で行う。展開後のイベントには、通常の tick 累積・ノート長処理・トラック開始オフセット・複数トラック統合を適用する。

## 実装前に固定する安全条件

1. **元データ境界を守る:** FC の参照 byte offset は、トラックデータ領域内かつ4-byteレコード境界に一致する場合だけ解決する。ヘッダー内、トラック外、未整列、FE より後ろの位置はエラーとして拒否する。
2. **失敗時は全体を拒否:** ループ展開に失敗したら、そのトラックの出力だけでなく文書全体のイベント出力を空にする。既に展開できたノートを成功結果として返さない。
3. **循環を検出:** FC チェーンごとに訪問済み FC レコード位置を保持し、同じ位置を再訪した時点でエラーにする。固定の深さ上限だけで安全性を担保しない。
4. **有限の展開予算:** F8/F9 の反復回数と FC 展開によりイベント数が増えるため、展開レコード数・出力イベント数に明示的な上限を設ける。上限到達は成功扱いにせず、説明可能なエラーにする。上限値は、実ファイルサイズと想定する妥当な曲長を踏まえて別途決定する。
5. **整数オーバーフロー防止:** tick 累積、反復回数×区間長、イベント数・byte offset の計算は加算/乗算前に上限を検査する。
6. **コマンドの役割を混ぜない:** F8/F9 と FC は別の展開規則として実装し、0x98 を FC と同一視しない。
7. **原順序を保持:** 展開イベントには元レコード位置と展開順を持たせ、同tickのイベント順序を決定的にする。

## 合成テスト計画

| ケース | 入力の要点 | 期待する結果 |
|---|---|---|
| F8/F9 の単純ループ | 小さなノート列、F9、ノート列、反復回数付きF8 | **実装済み**。合成テストで反復回数・tick・順序を検査 |
| F8 step=0 | 反復回数0 | **実装済み**。仕様未確定のため明示的に拒否 |
| 不対 F8 / F9 | 開始だけ、または終端だけ | **実装済み**。失敗し出力を空にする |
| F8/F9 のネスト | 入れ子の範囲 | **実装済み**。合成テストでイベント数・順序・tickを検査 |
| FC の有効参照 | 有効な整列済みレコード位置 | 正しい参照区間のイベント列を展開 |
| FC の連鎖 | FC が別の FC を参照 | tail-call規則を適用し、余分な戻り先を積まない |
| FC の終端位置 | 参照位置と同じ位置／後方の位置 | 同位置なら追跡を継続、後方なら繰り返し終了 |
| FC のヘッダー内参照 | byte offset が44未満 | 失敗し出力を空にする |
| FC の未整列参照 | 4-byte境界にない位置 | 失敗し出力を空にする |
| FC のトラック外参照 | トラック長を越える位置 | 失敗し出力を空にする |
| FC の循環 | 同じ FC 位置を再訪する参照チェーン | 無限展開せず失敗し出力を空にする |
| 展開予算超過 | 大きな反復数、または極端な連鎖 | 決めた上限で明示的に失敗し出力を空にする |
| 0x98 | FCに似た値を含むレコード | FC として解釈せず、未対応コマンドとして拒否 |

## 未決事項

- F8/F9 のネスト・複数ペア・反復回数の正確な意味と、step=0 の扱い。
- FC が指す参照先を含む範囲の端点条件を、複数の独立した合成ケースでどう表現するか。
- 展開予算の値と、その上限を「妥当な曲を拒否しない」ことの確認方法。
- `encoded_length` と実際に FE まで読んだレコード数の整合性を、ループ参照の範囲チェックにどう反映するか。
- F8/F9/FC が同じトラックに混在する場合の優先順位・相互作用。

F8/F9 の有限カウント部分だけを実装した。F8 step=0 の意味、FC、実ファイル互換性は未解決であり、RCP2 ループ全体への対応を意味しない。
