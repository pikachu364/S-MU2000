# RCP2 実装チェックリスト

この文書は、[JMPlayer RCP format notes](https://github.com/jihodaya/jmplayer/blob/main/docs/formats/en/rcp.md) を参照し、S-MU2000 の RCP2 対応状況を項目別に管理する。JMPlayer資料の確認済み表示は、S-MU2000側の実装・検証済みを意味しない。

## 判定方法

| 状態 | 意味 |
|---|---|
| 未確認 | 資料・コード・テストの確認がまだ |
| 資料確認 | 形式資料または参照実装の記述を確認 |
| コード確認 | S-MU2000の実装を確認 |
| 合成テスト確認 | 小さな人工データによるテストを確認 |
| CI確認 | 該当変更後のGitHub Actions成功を確認 |
| 実データ比較 | 許可されたRCPサンプルと参照出力を比較 |
| 実再生確認 | プレイヤー／音源で再生した結果を確認 |
| 未解決 | 根拠が不足し、仕様・原因を確定できない |

コードの存在、合成テスト、CI、実データ比較、実再生は別々の証拠として扱う。記録の時系列は [LOG.md](LOG.md)、確定事実は [FACTS.md](FACTS.md)、仮説は [HYPOTHESES.md](HYPOTHESES.md)、次の作業は [NEXT_STEPS.md](NEXT_STEPS.md) に置く。このチェックリストには現在の判定と未完了項目を集約し、日付付きの経過記録を重複して並べない。

## 4. コマンド対応

| コマンド | 形式上の役割 | S-MU2000の現状 | 残作業・制約 |
|---|---|---|---|
| `0x80`–`0x87` | ユーザーSysEx送信 | 実装・合成テスト確認済み | 実データの意味・実機再生は別途確認 |
| `0x90`–`0x97` | ヘッダー定義ユーザーSysEx | 実装・合成テスト確認済み | 8スロット、置換、F0/F7、checksum、dummy抑止。最新CI状態は履歴参照 |
| `0x98` | Track SysEx | 実装・合成テスト確認済み | 後続F7継続、テンプレート置換、checksum、tick進行を検査。未知高bit値の意味は未解決 |
| `0x99` | 外部コマンド | 実装・合成テスト確認済み | MIDIイベントを出さず、直後のF7継続をまとめてp0を進める。実データ上の意味は未確認 |
| `0xD0` / `0xEE` | Pitch Bend | alias実装・合成テスト確認済み | 実データでの出現・再生は未確認 |
| `0xD2` / `0xEA` / `0xEB` | Control Change | alias実装・合成テスト確認済み | 標準MIDI化できる範囲に限定 |
| `0xD3` / `0xEC` | Program Change | alias実装・合成テスト確認済み | 特殊ECは拒否する制約あり |
| `0xDD` / `0xDE` / `0xDF` | GSパラメータ書き込み | 実装・合成テスト確認済み | DT1 SysEx生成を検査。実機再生は別途 |
| `0xE1` | XG音色選択 | 実装・合成テスト確認済み | CC32=p2、Program Change=p1 |
| `0xE2` | GS音色選択 | 実装・合成テスト確認済み | CC0=p2、Program Change=p1 |
| `0xE6` | channel/port変更 | 実装・合成テスト確認済み | route変更、dummy/unrouted切替。Actions #338合格報告あり |
| `0xE7` | 基本テンポ比によるテンポ変更 | 実装・合成テスト確認済み | gradualテンポ曲線は未対応 |
| `0xF5` | Key Signature | 実装・合成テスト確認済み | 時間を進めず、tickと同tick順を検査 |
| `0xF6` / `0xF7` | コメント／継続 | 実験的実装・合成テストあり | F6後続F7を継続として扱う。完全な仕様確定ではない |
| `0xF8` / `0xF9` | ループ終端／開始 | 実装・合成テスト確認済み | 有限反復1〜126、ネスト、境界を検査。step=0や0x7f以上は安全側で拒否 |
| `0xFC` | 参照位置への移動 | 実装・合成テスト確認済み | 44-byteヘッダー基準offset、連鎖、終端復帰、循環防止、展開予算 |
| `0xFD` | 小節終端 | 未確認 | stepを時間加算しない可能性を含め確認 |
| `0xFE` | トラック終端 | 実装・合成テスト確認済み | FEで終了し、後続レコードを処理しない |
| `0x98` 内の `0xFF` | テンプレート値 | 未解決 | ValleyBell/Gearmulator/S-MU2000は未知高bit値をスキップ。置換規則の根拠なし |

時間を進めないコマンドのstepを通常時間として加算しないこと。コマンド単体の合成テストと、ループ・継続レコードとの組合せテストを区別する。

## 8. Roland DT1 / SysEx調査

| 項目 | 確認結果 | 残課題 |
|---|---|---|
| 0x98テンプレートの未知高bit値 | ValleyBellとGearmulatorは未知値をスキップ。S-MU2000も同様 | 元データの意図、実機への影響は未解決 |
| 0xFFの置換規則 | 形式資料に根拠なし。0x7E等への置換仮説は再計算で裏付けられず撤回 | 根拠なしの置換・checksum補正を行わない |
| GearmulatorのDT1 checksum error | 不一致時は当該DT1を拒否し、エラー通知。後続入力は別途処理可能 | ユーザーが過去に見た表示との同一性は未特定 |
| Gearmulatorの最低長 | body 9 bytes未満はchecksum検査前に無通知return | 実装・機種条件を混同しない |
| sample-01〜04のDT1 | 合計503件。500件はchecksum合計0、残り3件は8-byte bodyでchecksum byteなし。不一致0 | 静的event dumpの検査であり、実再生試験ではない |
| sample-04のmodel ID 0x56 | 26件中16件がRoland公式Part Rx OFF形式と一致。最大密度窓の8件もその一部 | 残り10件の用途は未特定 |
| 過去のCheck Sum Error表示 | 今回のsample-01〜04では88emu単独／Glosa経由ともエラー表示なしとのユーザー報告 | 別曲での発生源は未特定。今回4サンプルの原因として扱わない |
| 高密度SysExとタイミング競合 | SC-55mkIIに関するGearmulator changelog上の既知事例を確認 | SC-88系や今回サンプルに同じ不具合があるとは推定しない |

## 10. 完了判定

機能項目を完了にする際は、該当する証拠を分けて記録する。

1. 形式資料・参照実装の根拠。
2. S-MU2000コードの該当処理。
3. 合成テストの入力・期待値・実測値。
4. GitHub Actionsの実行結果（runまたは番号）。
5. 実データ比較の対象・参照版・イベント数・不一致数。
6. 実再生を行った場合は、ソフト・音源・経路・結果。

未実施の段階を完了扱いにしない。新しい調査結果は該当する項目へ統合し、古い状態や重複した日付付き追記を残さない。経過の保存が必要な場合だけLOG.mdへ記録する。
