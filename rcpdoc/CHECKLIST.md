# RCP2 対応チェックリスト（開発内部用）

この文書は、S-MU2000 における RCP2 対応の実装・検証状況を管理する内部資料です。外部プロジェクトの資料構成やチェック項目をそのまま転用せず、S-MU2000 の処理段階と検証工程に沿って整理します。作者向け・利用者向けの説明文書としては使用しません。

## 判定の区分

| 状態 | 意味 |
|---|---|
| 未確認 | 現時点で根拠を確認できていない |
| コード確認 | S-MU2000の該当処理を確認 |
| 合成テスト確認 | 人工的に作成した入力によるテストを確認 |
| CI確認 | 対象変更後のGitHub Actions成功を確認 |
| 参照比較確認 | 参照実装の出力とイベント列を比較 |
| 実再生確認 | プレイヤー・音源を用いた再生結果を確認 |
| 未解決 | 仕様または原因を確定する根拠が不足 |

各段階は独立して判定します。コードが存在することだけでテスト済みとはせず、CI成功だけで実ファイル再生済みとも扱いません。

記録の役割:
- [FACTS.md](FACTS.md): 根拠を確認した事実
- [HYPOTHESES.md](HYPOTHESES.md): 未確定の仮説と検証方法
- [NEXT_STEPS.md](NEXT_STEPS.md): 次に行う作業
- [LOG.md](LOG.md): 日付順の作業履歴
- [README.md](README.md): 資料の読み方と運用ルール

## 6. 参照実装とのイベント比較

現在の比較基準では、許可された検証用データ4件について、参照コンバーターとのイベント列比較が合計94,554イベント、不一致0となっています。個別の曲名・ファイル名・非公開データの識別情報は、このチェックリストには記載しません。

| 確認項目 | 状態 | 注意点 |
|---|---|---|
| イベント総数 | 確認済み | 対象データの範囲内 |
| イベント内容・順序 | 確認済み | 対象データの範囲内で完全一致 |
| 同一tickの順序 | 現行比較で一致 | 追加データでも継続確認 |
| SysExの意味的妥当性 | 別途確認が必要 | イベント列一致だけでは音源側の受理を保証しない |
| 全RCP2ファイルとの互換性 | 未確認 | 限定された比較結果を一般化しない |
| 実際の再生音 | 別途確認 | 参照イベントとの一致と音の一致は別 |

## 7. SysEx・音源側の検証

| 項目 | 確認結果 | 未完了・注意点 |
|---|---|---|
| DT1 checksum | 検証用イベント列503件を静的検査し、不一致0。うち3件はchecksum byteを持たない短い形式 | 静的検査であり実再生ではない |
| 短いDT1の扱い | Gearmulatorの該当実装では最低長未満をchecksum検査前に終了 | 機種・実装固有の挙動として扱う |
| checksum error後の処理 | Gearmulatorのソース・テスト構成で後続処理経路を確認 | 今回のS-MU2000実再生での確認ではない |
| 高密度SysEx | 検証用イベント列の時間密度を集計 | 密度だけでエラー原因と断定しない |
| 過去に報告された音源エラー | 今回の検証用データでは再現報告なし | 別データでの発生源は未特定 |
| 機種固有のDT1解釈 | 一部の公式資料・参照実装を確認 | すべての機種に一般化しない |

## 9. 完了判定

項目を完了にする際は、次の証拠を区別して記録します。

1. 形式資料または参照実装の根拠
2. S-MU2000コードの該当処理
3. 合成テストの入力・期待値・実測値
4. GitHub Actionsの実行結果
5. 参照比較の対象範囲・参照版・件数・差分数
6. 実再生を行った場合のソフト・音源・接続経路・結果

新しい結果は該当する項目へ統合し、古い状態や重複した追記を残しません。経過の保存が必要な場合だけLOG.mdへ記録します。非公開サンプルの曲名、ファイル名、生データ、識別可能なダンプは公開用文書へ転記しません。
