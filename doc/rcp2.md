# RCP2 対応設計メモ（ドラフト）

**状態:** 実装初期段階（固定ヘッダー、トラック走査、未解釈シーケンス解析）  
**対象:** S-MU2000 での RCP2（`.rcp`）解析・再生  
**目的:** 実装の分担、既存コードとの接続、未確定事項を整理する。

## 現在の実装状況

- `src/rcp.h` / `src/rcp.cpp` で RCP2 の識別文字列、固定ヘッダー（0x586 bytes）、トラックヘッダー（0x2c bytes）を読み取る。固定ヘッダーからタイトル、コメント、TPQ、テンポ、拍子、キー、PlayBIAS の生バイト、トラック数を取得し、トラックヘッダーから長さフィールド、ID、リズム設定、MIDIチャンネル、キー値、tick offset、ミュート、名前を取得する。
- `parse_tracks` が固定ヘッダーのトラック数に従ってトラックを走査し、トラック長の下限・ファイル末尾境界・各トラック内の FE 終端を検証する。長さフィールドは参照資料に従い、長さフィールド自身を含む全トラック長として扱う。
- `build_intermediate` が文書ヘッダー、トラックヘッダー、未解釈の 4 byte レコードを中間表現にまとめる。各レコードのトラック内インデックスと生パラメーターを保持し、tick やコマンド意味論は推測しない。失敗時は出力を空にする。
- 4 byte のシーケンスレコードを生データのまま読み、FE (Track End) までを返す `parse_sequence` を追加した。コマンドの展開・時間解釈は行わず、終端なし・途中で切れた入力は拒否する。
- `verify` に合成したヘッダー／トラックヘッダー／シーケンスレコードのテストを追加した。実データや商用曲は含めない。
- Makefile と CMake の共通コアに登録した。
- **MIDI への変換・再生は未実装。** この段階では RCP2 の曲を再生できない。イベントの時間計算、特殊コマンドの意味、トラック終端後の余剰バイトの意味は未確定。
- ヘッダーの項目位置は [ValleyBell/MidiConverters の RCPFormat.txt](https://github.com/ValleyBell/MidiConverters/blob/master/RCPFormat.txt) の表を参照。これは第三者による解析資料であり、公式仕様として断定しない。
- 識別文字列は既存コンバーターの判定を参考にした。ヘッダー全体のレイアウトやイベント仕様は、実ファイルと複数実装の照合後に確定する。


> この文書は設計案であり、RCP2 の正式仕様や実機との完全な互換性を示すものではない。既存実装で確認した挙動と、形式全体で確定した仕様を区別する。

## 1. 対象範囲

初期実装では RCP2（`.rcp`）を対象とする。RCP3（G36/R36）は将来の拡張候補とし、CM6/GSD は初期対象外とする。

既存プレイヤーやコンバーターは、ファイル形式と変換結果を調べるための参考資料として扱う。特定実装で確認できたヘッダー長、イベント形式、コマンドの意味などを、そのまま全 RCP2 ファイルに共通する正式仕様とみなさない。

## 2. 推奨する処理構成

処理を次の段階に分ける。

1. **ファイル解析:** ヘッダー、トラック情報、イベント列を読み取る。
2. **中間表現:** トラック、イベント種別、パラメーター、相対位置などを保持する。
3. **イベント展開:** テンポ、ループ、小節リピート、継続データなどを処理する。
4. **時間変換:** 展開後のイベントを時間情報付き MIDI イベント列へ変換する。
5. **再生側への引き渡し:** GUI、VST3、オフラインレンダーなど、それぞれの実行環境に適した方法でイベントを処理する。

ファイル解析・イベント展開と、S-MU2000 固有の MIDI／SysEx 配送は分離する。これにより、RCP の解釈と、音源側での再現性を別々に検証できる。

## 3. 既存実装から得られる手掛かり

調査対象の既存 RCP2 プレイヤーには、ヘッダー解析、イベント処理、ノート終了管理、テンポ変更、ループ／リピート、SysEx 生成などの処理がある。これらは実装上の参考になる一方、実装間の挙動比較と実ファイルでの検証が必要である。

参考資料:

- [Gearmulator RcpFilePlayer_test.cpp](https://github.com/masanaohayashi/gearmulator/blob/codex/pr-rcp-player/source/ronaldo/88emu/88emuplayer/RcpFilePlayer_test.cpp)

- [ValleyBell MidiConverters / rcp2mid.c](https://github.com/ValleyBell/MidiConverters/blob/master/rcp2mid.c)

既存実装のコードを流用する場合は、ライセンスと帰属表示の条件を先に確認する。仕様の調査とコードの再利用は分けて扱う。

## 4. S-MU2000 への接続で注意する点

S-MU2000 には MIDI イベントを処理する既存経路があるが、フロントエンドによってタイミング管理とイベントの受け渡し方が異なる。

- VST3 側にはサンプル位置付きイベントを処理する経路がある。
- GUI 側の MIDI 入力経路は、MIDI バイト列を音源へ渡す処理を含む。
- `render.exe` にはオフラインで MIDI を処理する経路がある。
- バイト列キューを、サンプル位置付きイベントのスケジューラーと同一視しない。

共通処理が生成するイベントの時間表現を決めたうえで、各フロントエンドへの配送方法を個別に設計する。ブロック境界、同時刻イベントの順序、既存入力との競合、再生停止・再開時の状態は確認が必要である。

## 5. テスト方針

第三者の楽曲ファイルをリポジトリに保存せず、テストコードで小さな合成バイト列を生成する。

推奨する順序:

1. 最小ヘッダーと空トラック
2. 1 音のノートオン／ノートオフ
3. step と gate によるイベント時刻
4. テンポ変更
5. ループと小節リピート
6. ユーザー SysEx と継続データ
7. 不正・途中で切れた入力
8. 既存コンバーターとの出力比較

各テストでは、入力バイト列、期待するイベント列、実際のイベント列を分けて記録する。イベント内容と時刻の検証を、音源から出る音の一致とは別に扱う。

既存テスト方針も参照する: [S-MU2000 回帰試験](https://github.com/tarboh/S-MU2000/blob/main/doc/testing.md)。

## 6. 未解決事項

次の項目は、確認できるまでは確定仕様として扱わない。

- ループの入れ子、終了条件、特殊値
- SameMeasure（同小節参照）の意味と展開順序
- 相対テンポやテンポ変化の時間計算
- ユーザー SysEx の特殊値、チャンネル挿入、チェックサム
- MIDI ポートとトラックの対応
- 同時刻に発生するイベントの順序
- 未知コマンドや不正入力の扱い
- GUI、VST3、オフラインレンダー間のタイミング整合性

観察結果には、可能な限り再現手順、参照した実装・ファイルの種類、確信度を添える。実ファイルや既存コンバーターの結果と矛盾する場合は、差分を記録してから仕様判断を行う。

## 7. データと公開範囲

テストには合成データを優先し、商用・第三者の楽曲ファイル、ROM、ファームウェアなど公開に適さないデータを追加しない。調査途中の推測は確定事項として記述せず、未解決事項として残す。
