# RCP2 対応 — 開発説明書

更新日：2026-10-30  
対象リポジトリ：`pikachu364/S-MU2000`  
対象ブランチ：`feature/rcp2-parser-skeleton`

この文書は、S-MU2000 における RCP2（`.RCP`）対応の全体像、現在の実装範囲、検証結果、未完了事項を説明する入口資料である。詳細な調査記録・日付順ログ・項目別チェックは `rcpdoc/` に分けて記録する。

> **重要:** RCP2 の一部機能が動作することと、すべての RCP2 ファイルとの完全互換性は同じではない。参照コンバーターとのイベント比較、合成テスト、CI、GUI での実ファイル再生は、それぞれ別の検証として扱う。

## 1. 目的と対象範囲

S-MU2000 の GUI プレイヤーで RCP2 の曲ファイルを読み込み、既存プレイヤーの MIDI イベント配送経路で再生できるようにする。

- 主対象：RCP2（`.RCP`）
- 将来の拡張：RCP3 系形式は、RCP2 の解析・イベント展開の境界を整理したうえで別途検討する
- 初期対象外：CM6 / GSD
- 形式資料や既存コンバーターは調査・比較の参考にする。特定の参照実装の挙動を、そのまま公式仕様と断定しない

## 2. 処理の流れ

RCP2 の読み込みは、既存の SMF（Standard MIDI File）読み込み経路と分け、解析結果を既存プレイヤーが扱うイベント列へ変換する。

1. **形式判定・ヘッダー解析** — RCP2 の識別、文書ヘッダーとトラック情報の取得
2. **トラック／レコード解析** — トラック境界と 4 byte レコード列を読み取る。FE をトラック終端として検査する
3. **中間表現の構築** — ヘッダー、トラック属性、元レコード情報を保持する
4. **イベント展開** — 対応コマンドを意味のあるイベント列へ展開し、ループ等を処理する
5. **時間変換** — tick を秒へ変換する
6. **MIDI 出力への変換** — トラックごとの port / channel 割当を反映し、MIDI byte 列を作る
7. **既存プレイヤーへ引き渡す** — GUI プレイヤーの通常の再生・停止・シーク等のイベント経路を利用する

解析、RCP コマンドの意味解釈、MIDI 出力、プレイヤー配送を分離する。これにより、ファイル構造の問題と音源・再生側の問題を別々に調査できる。

## 3. 主な実装箇所

| ファイル | 役割 |
|---|---|
| `src/rcp.h` / `src/rcp.cpp` | RCP2 のヘッダー／トラック解析、中間表現、イベント展開、時間変換、MIDI イベント化 |
| `src/ui/player.cpp` | RCP2 と SMF の形式判定、RCP2 変換パイプライン、既存プレイヤーへの接続 |
| `src/verify.cpp` | RCP2 の合成入力・境界条件・変換パイプラインの検証 |
| `tests/verify.txt` | verify の期待出力 |

実際の関数名・現在のテスト範囲はソースコードを正とし、この表は入口として使う。

## 4. 現在の実装範囲

現在の実装は、RCP2 の全コマンドを網羅するものではない。対応済みコマンドの一覧と個別の根拠・テスト状況は [CHECKLIST.md](../rcpdoc/CHECKLIST.md) を参照する。

主な実装領域：

- 固定ヘッダー、トラックヘッダー、4 byte レコード列の解析
- FE 終端、トラック境界、入力長の検査
- 中間表現と複数トラックのイベント時系列統合
- ノート、ノートゲート／Note Off 相当イベントの展開
- テンポ・キー署名など一部の時間／メタイベント
- MIDI チャンネルイベントと一部の機種固有 SysEx
- F8/F9 の有限ループ展開、FC の参照展開と連携処理
- E6 などによるトラックの出力先切り替え
- 既存プレイヤー API への RCP2 読み込み接続と、失敗時に部分的な曲を追加しない処理

未対応・制限のあるコマンドが入力に含まれる場合、未対応部分を黙って捨てて成功扱いにするのではなく、原則として読み込みを拒否する。対応範囲を広げるときは、コマンド単位で入力消費、状態変更、tick 進行、出力イベントを確認する。

## 5. 検証結果の読み方

検証結果は、次の段階を混同しない。

| 検証段階 | 確認できること | それだけでは確認できないこと |
|---|---|---|
| ソースコード確認 | 処理が実装されていること | 実行時に正しく動くこと |
| 合成データテスト | 作成した入力と境界条件に対する期待動作 | 実ファイル全般との互換性 |
| GitHub Actions | CI 上でビルド／テストが成功したこと | 実機や GUI での再生品質 |
| 実ファイルの構造解析 | 実ファイルのヘッダー・トラック・イベント列を処理できること | 参照出力や音の完全一致 |
| 参照コンバーターとのイベント比較 | 指定サンプル・指定条件でイベント列が一致すること | RCP2 全体の仕様適合、実機再生、聴感上の完全一致 |
| GUI／実機での再生 | 実際に確認した環境での読み込み・再生結果 | 未試験ファイルや別環境での動作 |

### 参照サンプル比較

2026-10-29 時点の開発記録では、private sample-check の4サンプル（BUTTFLY、FC、WINGS_55、L_WING88）について、ValleyBell 参照コンバーターとの比較で合計 94,554 イベントが一致し、各トラックの件数も一致したと記録されている。

これは選定した4サンプルにおけるイベント比較結果であり、RCP2 全コマンド・全ファイルの互換性や、実機での再生結果を保証しない。サンプル本体は非公開資料リポジトリに置き、公開コードリポジトリへ曲データをコピーしない。

## 6. 未完了・継続調査

優先順位と最新状況は [NEXT_STEPS.md](../rcpdoc/NEXT_STEPS.md) を正とする。主な継続項目は次のとおり。

- FC 参照展開の予算超過、深い連鎖、端点条件などの境界テスト
- F8 step 値など、参照資料と実データの根拠が不足する条件の確認
- 実ファイルを使ったプレイヤー API の読み込み・エラー伝播確認
- 未対応コマンドや仕様未確定コマンドの調査・段階的な対応
- GUI での実ファイル再生と、再生結果の記録

未確認の意味を推測で補わない。特に SysEx の未知値、チェックサムの自動修正、コマンドごとの delay の扱いは、根拠と再現テストが揃うまで確定しない。

## 8. 開発時の安全ルール

- 作業ブランチは `feature/rcp2-parser-skeleton` とする。別用途の `feature/rcp2-draft-pr` と混同しない。
- `main` を直接変更しない。
- ローカルの未コミット変更を上書き・reset・削除しない。
- Yamaha ROM、ファームウェア、実機由来データをアップロードしない。
- 実曲サンプルは許可された非公開資料リポジトリで扱い、公開リポジトリには含めない。
- ValleyBell、JMPlayer、Gearmulator 等は調査・比較の参考とし、コードを流用する場合はライセンス条件を別途確認する。
- 実行していないテストを成功扱いにしない。CI 合格、参照比較、実再生のどれを確認したか明記する。
